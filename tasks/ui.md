<a id="contracts"></a>
## Что приходит в UI

Событие `plan` несёт полный `TripState`. Панель всегда рисует последнее состояние, после F5 план берётся из `GET /api/trips/{session_id}`. Главное:
- `request` — что сказал пользователь, `search` — во что это превратилось при поиске. Чипы допущений = `request.assumptions` + `search.assumptions`;
- `pending_question` — `{slot, text, options}`, пока агент ждёт ответа. Ответ кнопкой отправляется как `text`, ровно текст кнопки;
- `places` — названия мест: slug → «Москва». Нет slug в `places` — выводи сам slug;
- `packages[]`: `tier`, `total`, `price_breakdown` (ключи `hotel`, `outbound`, `inbound`, `transfer`), `why`, `tradeoffs`, `risks`, **новое на этапе 1** — `sources`.

API, все маршруты настоящие:
- `POST /api/chat` с `{"session_id", "text"}` или `{"session_id", "action": {"type": "select_package", "package_id"}}` → SSE;
- `GET /api/trips/{session_id}` → `TripState`, плана нет → 404;
- `POST /api/orders` с `{"session_id", "package_id", "idempotency_key"}` → 201; повтор с тем же ключом → тот же заказ; 404 / 409 — как в MVP.

Точные модели — `domain/`, события — `agent/events.py`.
