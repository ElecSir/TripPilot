# Кейсы оценки разбора запроса

Файл `parse.yaml` — данные зоны data для прогона оценки (`evals/run.py`, задача rag).
Кто читает: прогон гоняет каждую фразу через правила (`parse_request`) и, если есть ключ,
через LLM (`understand`), и считает долю верных полей отдельно для каждого режима.

## Формат кейса

```yaml
- text: "Хочу на море в Турцию в ноябре вдвоём с ребёнком 5 лет"
  today: 2026-10-26
  expect: {destination: antalya, month: 11, children_ages: [5], tags: [sea]}
```

- `text` — фраза человека как есть.
- `today` — «сегодня» для разбора: от него считаются «завтра», «через неделю» и перенос года.
- `expect` — **только поля, важные в этом кейсе**. Остальные поля не проверяются: правила
  могут положить в них что угодно.
- `base` — необязательный запрос «до изменения» (плоский словарь полей запроса). Нужен для
  кейсов-изменений: фраза прогоняется через `parse_change` поверх `base`, а `expect`
  описывает только изменившиеся поля. Это расширение формата из `tasks/data.md`; согласовано
  по смыслу с rag — если прогон захочет иначе, правится здесь и в `evals/run.py` вместе.

Поля `expect` совпадают с полями `TripRequest`, кроме состава: `adults`, `children_ages`,
`pets` лежат в `party`, но в кейсе пишутся плоско. Даты — строкой `YYYY-MM-DD`,
бюджет — числом рублей строкой или числом.

## Что покрыто

78 кейсов: города, страны и алиасы, «на»/«в начале», даты (включая перенос года и диапазоны),
состав и дети, животные, бюджет, качества и изменения плана. Все фразы таблицы PR #13
из `tasks/data.md` входят в файл — за этим следит тест.

## Как менять

Кейсы проверяются тестом `tests/unit/test_eval_cases.py`: он требует, чтобы правила давали
ровно записанные поля. Правка кейса без правки разборщика (или наоборот) роняет тест —
это и нужно: цель кейсов не «зелёный CI», а честная цифра для жюри.

```powershell
uv run pytest tests/unit/test_eval_cases.py -q
```
