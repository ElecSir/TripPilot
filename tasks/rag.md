<a id="goal"></a>
## Цель этапа 1

Чтобы модель заработала, нужны три вещи из твоей зоны: надёжный клиент LLM, хорошие фрагменты базы знаний для объяснений и цифры, по которым видно, что с моделью стало лучше. Модель вызывают функции data: разбор запроса (`understand`) и объяснения (`narrate`). Им нужно, чтобы любой сбой LLM приходил как `LLMUnavailable`, а `context` отдавал нужные разделы. Лид и ui подключаются к тебе по необходимости.

Главное правило RAG не меняется: **база знаний — это знания, а не факты.** Цены, расписания и наличие берутся из таблиц data, а не из текстов. И второе: у жюри нашего ключа не будет, поэтому всё, что ты делаешь, обязано работать и без него (поиск — полнотекстовый, эмбеддинги — пропускаются).

Перед началом подтяни `main`: `git pull origin main`.

<a id="pr-11"></a>
### PR #11 — база знаний, адаптер LLM, индекс и поиск (влит)

Итог ревью: задачи 1–4 выполнены, CI на слиянии зелёный. На живой БД 12 документов и 60 фрагментов, повторный bootstrap ничего не дублирует, `search("с детьми", destination="antalya")` находит «Анталья › С детьми». Строка `COPY data ./data` в dev-образе принята: без неё тест на 12 файлов не видит базу.

Что поправить (задача 1):
1. **`LLMUnavailable` на любой сбой.** Сейчас после исчерпанных повторов наружу летят исключения `openai` (сеть, таймаут, 429, 5xx), а 401/403 не превращаются ни во что. Нужно `raise LLMUnavailable(...) from error` после повторов и сразу на 401/403. Вторая неудачная проверка схемы в `structured()` — тоже `LLMUnavailable`. **Теперь это часть контракта** (правило в `AGENTS.md`): ядро ловит только `LLMUnavailable` и уходит на правила, а чужое исключение обрывает ход.
2. **Обёртка ```json.** Многие модели заворачивают JSON в ```json … ```. Срезай её перед `model_validate_json`, иначе на неё зря уходит повтор.
3. **Ключ документа — файл, а не `title`.** Сейчас переименование заголовка создаёт дубль, а удалённый файл остаётся в индексе. Храни имя файла в `source_url` и ищи документ по нему; файла больше нет — удали документ с фрагментами.
4. **Поиск на естественных фразах.** «когда», «лучше», «можно», «ли» — стоп-слова, а слова запроса должны найтись все сразу:
   - «можно ли с собакой» по Сочи → 0 результатов;
   - «питомец», «собака» по всей базе → 0;
   - заголовок «Когда лучше» целиком из стоп-слов, по нему раздел не найти.

   Нужно: если строгий запрос ничего не нашёл, искать по любому из слов; синонимы к разделам (собака, кошка, питомец → животные; сезон, погода, климат → «Когда лучше»; ребёнок, семья → дети), например строкой ключевых слов во фрагменте при индексации.
5. Галочки в задании не были отмечены — отмечай по ходу.

### 4. Эмбеддинги и гибридный поиск — после ключа
- `embed_index(session, llm)` в `rag/index.py`: эмбеддинги для фрагментов без `embedding` или с другим `embedding_model`, пачками по 64, модель записывается в `embedding_model`. Заглушка уже лежит в `rag/index.py`, а bootstrap (`cli.py`) уже её вызывает (L1): замени тело.

## Контракты этапа 1

Уже в `main` (задача L1 лида), вместе с заглушками `context` и `embed_index` в твоих файлах. Ниже — выжимка, точные сигнатуры — в `ports.py`; если выжимка разойдётся с кодом, прав код.

```python
# ports.py — KnowledgeBase, новый метод (ты реализуешь в PostgresKnowledgeBase)
async def context(self, request: TripRequest, destination: str, *,
                  limit: int = 4) -> list[KnowledgeHit]: ...

# ports.py — LLMUnavailable: любой сбой LLM после повторов адаптера (правило в AGENTS.md)

# rag/index.py — вызывает bootstrap (cli.py, лид) после build_index
async def embed_index(session: AsyncSession, llm: LLM) -> None: ...

# domain/offers.py — сюда data кладёт фрагменты, на которые ссылаются объяснения
Package.sources: list[KnowledgeHit] = []
```

Кто вызывает твой код:
- оркестратор: `knowledge.context(request, destination)` после сборки пакетов, результат — в `narrate` (data);
- `understand` и `narrate` (data): `llm.structured(...)` и `llm.complete(...)`;
- приложение: `make_llm(settings)` и `PostgresKnowledgeBase(sessions)` в `api/main.py`, `embed_index(session, make_llm(settings))` в bootstrap — уже подключено (L1).

Ключ LLM задаётся в `.env`: `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`, `EMBEDDINGS_MODEL`. Ключ выдаёт лид. Храни его только в `.env`, никогда в чате, коде, тестах и PR. В тестах — подменённый клиент или `FakeLLM`.
